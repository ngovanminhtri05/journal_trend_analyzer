4. What was fixed — test-layer only (no app behaviour changed)

The initial executions produced failures traced to mismatches between the test finders and the real widget tree — the tests had never been run against the built UI. The root cause of four feature failures was a single fact:

Root cause · StatCard renders labels UPPER-CASED stat_card.dart uses Text(label.toUpperCase()). Patrol's text finder is case-sensitive, so $('Total publications') could never match the on-screen TOTAL PUBLICATIONS. Fixed by asserting the real rendered text (e.g. $('TOTAL PUBLICATIONS'), $('PUBLICATIONS ACROSS TOP JOURNALS')).
TC4 / TC5 · Ambiguous wait anchor The wait anchored on "Top journals", but the search-bar hint ("Top journals for a topic…") also contains that text, so the wait passed before results loaded. Re-anchored on the success-only summary card PUBLICATIONS ACROSS TOP JOURNALS.
TC8 / TC11 · Sign-out button below the fold The Profile list is scrollable and the Sign out button sits at the bottom (not built until scrolled into a lazy list). Added .scrollTo() before asserting / tapping it.
TC3 · Home most-influential card under a fixed-height chart On the Home overview the paper card sits below a 240 px interactive fl_chart (which absorbs drag gestures) and can be absent when a topic has no cited works. Re-routed TC3 to open a publication from a journal's chart-free "Most cited publications" list — a deterministic path that still verifies the Publication Detail screen (Authors / Abstract).
TC1 · Cold sign-in timeout The first cold sign-in runs Firebase auth plus the startup RemoteConfig fetch (up to a 10s timeout) before the shell renders. The wait for the NavigationBar was raised from 30s to 60s so the cold path completes.
TC1 / TC11 · Device prerequisite (R2) These drive the native Google chooser, which needs a real account on the device. A Google account was added to the emulator (Settings → Add account); the chooser then resolves Selector(textContains: '@') to that account.

No production code was modified — the app behaves as designed; only the E2E assertions/timeouts were corrected to match the real UI. flutter analyze integration_test: No issues found.
